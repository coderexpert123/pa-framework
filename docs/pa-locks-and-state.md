# pa — locks, build & state (extracted from pa/CLAUDE.md 2026-09-15)

- **Locks & state**: `reservations.ts` claims are TTL-based, advisory, per-path; the `@build` reservation is auto-acquired by build/test (build-lock.ts — never claim by hand). The dist-identity guard (`assertDistFresh`) fails closed on stale dist — build before every test (`PA_ALLOW_STALE_DIST=1` is the bisect escape). `distLayout` carries one arm per compiled package (`pa` / `bot` / `voice-inbox`) — a new package's runner that passes its own pkg label needs its arm added in build-lock.ts FIRST, else the unknown pkg silently falls through to PA's layout and the guard refuses against the wrong stamp (voice-inbox ran guardless until 2026-09-05 for exactly this reason). Blackboard locks are PID+heartbeat with classifyLock eviction (dead→evict, alive+stale→grace that still blocks). Renewal is tri-state (AI-179, 2026-09-03): `renewHeartbeat` returns `updated`/`row-absent`/`write-failed`; a write failure retries on the `PA_HEARTBEAT_WRITE_RETRY_MS` ladder (default 1 s/5 s/15 s) and `startLockRenewal` verifies the row (`peekLockRow`) before firing `onLost('purged')` — a transient EPERM on the atomic-replace rename no longer aborts a healthy run. `pa run` exits non-zero on failure (`exitCodeForCommandResult`: success → 0; `exitCode` 1–255 passthrough; else 1) — chains' `on_failure` now actually fires; the bot's spawns stay fire-and-forget by design.
- **Mutate contract** (AI-177 fix): `reservations.mutate`'s fn returns `{result, logEntries}` — decision logs flush only AFTER the store write commits. `renew(id, {session})` is owner-checked. `safeLockOptions({compromisedPolicy})`: 'fail' tags + routes rejection for reservations (never throws from the timer).
