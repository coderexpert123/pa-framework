# pa — test discipline (extracted from pa/CLAUDE.md 2026-09-15)

- **Test discipline**: scoped runs via `npm test -- <bare-basename>` (bare = the `.test` suffix stripped ENTIRELY — `npm test -- build-lock`, not `build-lock.test`; the filter has no `.test` fallback and exits 1 "No test files matched"); the run-tests.mjs dark-file detector fail-closes on zero-test files; inherited `NODE_TEST_CONTEXT` can silently skip all files in spawned runners — NOT stripped by the runners (a test spawning the runner must delete it itself, see runner-env-scrub.test.ts). Both run-tests.mjs wrappers scrub deployment-env flags (`PA_RICH_MESSAGES` etc., list in `src/lib/test-env-scrub.ts`) from the suite spawn — `pa run` injects all secrets.env values into LLM-worker shells, so gate-run tests otherwise inherit live feature flags (AI-199: PA_RICH_MESSAGES=1 rerouted worker replies over /sendRichMessage and failed 12 subtests on every push-gate run). When running suites by hand, leave `PA_TEST_TMP_DIR` unset unless you mean to change the maintenance allowlist (a test pins its `C:/wt/tmp` default), and never point TMP/TEMP at a directory inside a git worktree — walk-up fixtures resolve the worktree's `.git` and their expected rejections go missing. A scoped filter naming multiple basenames drops a nonexistent one SILENTLY (2026-09-11) — `npm test -- worker-slots rate-limits` prints a complete-looking `# fail 0` while `rate-limits` matched zero files, since the explicit "No test files matched" refusal fires only when EVERY name misses. A test calling `catchupCommand()` against a fresh temp `PA_HOME` pays the FULL declared-maintenance pass (2026-09-11) — ~30 jobs, several spawning real python subprocesses (`restore-drill`, `redteam-recurring`), ~187 s observed — so catchup tests share one temp home across cases and never mint one per test. A test that dispatches two or more REAL skills concurrently must pin `concurrency_limit` in its own fixture config (2026-09-12): the live dynamic worker-slot governor runs inside the test process and can throttle the admission gate under real machine load, making the second skill wait — an S7 test read that as a fire-and-forget failure until the limit was pinned to 8. **The machine suite lock (`C:/wt/test.lock`) is holder-identifiable (2026-09-13, `pa/scripts/testlock.mjs`)**: take it with `node pa/scripts/testlock.mjs acquire <session-label>` before a suite run and release with `release <session-label>` after — `HOLDER` (`{session, pid, at}`) inside the lock dir names the holder, `status` prints it with zero process archaeology, a refused release names the holder too, and a stale no-HOLDER (pre-convention) lock is cleared by `acquire --remove-stale` (lead-sanctioned per multi-session-protocol Rule 18) instead of CIM archaeology. **`acquire` does not short-circuit a lock your own session already holds (2026-09-18)** — a second call polls against itself every 60 s to the 30-minute timeout, so check `status` for your own label before re-running an `acquire` whose result looked ambiguous. Tests inject `PA_TESTLOCK_DIR` (never touch the machine-global default) with matching timing knobs `PA_TESTLOCK_POLL_MS`/`PA_TESTLOCK_WAIT_MS`/`PA_TESTLOCK_GRACE_MS`; the .mjs is never compiled — tests spawn the real CLI file and reach the pid-match branch through the module's exported functions.
- **Fixtures that seed a rolling-window cutoff must compute their timestamps relative to `Date.now()`, never hardcode an absolute date (found 2026-09-10, `feedback-analyzer.test.ts`)**: `analyzeFeedbackRules`'s `compileReactionCandidates` filters seeded `decisions.sqlite` rows on `ts >= now - ANALYSIS_DAYS days`. Two reaction rows were seeded with a literal `2026-08-27T0{9,10}:00:00.000Z` — valid the day the AI-165 WP-B commit landed (2026-08-28), silently false 13 days later once real time passed the 14-day mark, deterministically failing 2 subtests (`analyzeFeedbackRules` short-circuits before calling the runner when both turns and candidates are empty). Not a flake, not a product bug — proven by stashing just the test file and rebuilding: pre-fix 20/22 pass, post-fix 22/22. Any fixture feeding a `days`/`ANALYSIS_DAYS`-style cutoff needs a `Date.now() - n*86400000` timestamp, not a string literal. Same class, 2026-09-14: the synthetic-429 fixtures in `rate-limits-classifiers.test.ts` (and the bot's twin) carried a literal `2026-04-20` reset — a past-dated reset makes `classifyClaudeErrors` skip the reset-parse arm and fall to the default, so the bot's `usage-limit-session` assertion read `unknown` (the reset date must be computed forward from `Date.now()`).
- **Stale dist → one managed rebuild, not a bare refusal (AI-255 WP-G, 2026-09-16)**: both run-tests.mjs wrappers route the AI-180 guard through `pa/scripts/dist-guard.mjs` (`ensureFreshDist`) — a `DIST_STALE` result runs the package's own `scripts/build.mjs` inline ONCE (the build takes `@build` itself through `withBuildLock`, so it serializes with every other gate), re-asserts freshness, and only then runs; a failed build or still-stale re-assert refuses as before. `PA_NO_AUTOBUILD=1` restores refuse-fast for callers that manage their own builds (wave integrators, CI); `PA_ALLOW_STALE_DIST=1` still warn-and-continues inside `assertDistFresh` and never reaches the rebuild arm. `dist-guard.mjs` is side-effect-free on import — its test injects `assertFresh`/`runBuild` fakes rather than compiling anything.
