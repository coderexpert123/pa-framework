- **docs-lint trim counter** (`tests/docs-crossref.test.ts`, fix 305246a 2026-09-03): split detection = one memoized `git show --name-status -- '*.md'` probe per trim candidate (`A` status = split → counter reset); `git log --numstat` CANNOT mark new files (a created file reads as `added<TAB>0<TAB>path`, identical to an add-only modify, and the per-file query never lists the new file's row anyway). Commits stream OLDEST-FIRST (`--reverse`) so a split's reset clears only pre-split trims — newest-first leaves them counted when the split is the window's newest trim. Tool-layer gotcha found here: the old regex carried a literal backspace control byte where a `\b` escape was intended (written somewhere in its tool path), making it silently unmatchable — byte-scan source (`ord(c) < 32` sweep) when a "never matches" regex is suspected.

Convention after the voice-inbox raise (13,200): the row carries numbers + dates + one phrase; the full raise rationale (enumerated sections, evidence) lives in the raise-class comment next to `projectClaudeBudgets` in `tests/docs-crossref.test.ts`. Two more from the same wave: (1) a budget ruling's basis number goes stale FAST mid-wave — voice-inbox went 12,463 → 13,168 committed within 30 minutes of its ruling (two feature commits), so measure the LIVE COMMITTED file (`git show HEAD:<path>`, CRLF-normalized like `budgetLength`) before coding the constant, not the worktree mid-land figure the ruling quoted; (2) a balanced one-line doc edit (1 insertion/1 deletion in numstat) is NOT a trim — the counter classifies a commit as a trim only when summed deletions EXCEED summed insertions, so budget-sync edits that swap wording 1:1 don't consume the 24h trim window. (3) the mirror also drifts SILENTLY in the other direction — the 2026-09-14 four-file raise (d9414dd) found the knobs-catalog row still saying 28,000 against the code's 37,000 (stale since the 09-10/09-11 raises; corrected to 37,500 there) and the auto-managed row still 29,000 against the code's 33,000 (open, reported) — the test header's "numbers MUST match" has no enforcing test, so every raise must check BOTH directions: grep the doc's rows against the constants being written, never only write the new number.
- **public-sync's skip filter is FILE-shaped; tar directory members need their own handling (2026-09-04):** `git archive` emits a DIRECTORY member for every parent of an extracted file, and those members are never in `computeSkippedPaths`' output (check-ignore lists files only) — unhandled, a sync whose file skips all worked still leaves EMPTY directory husks of excluded trees in the mirror (pa-public carried empty `plans/` and `projects/fitness-data-sync/` after 2026-09-04 03:35 IST; the "filter didn't skip" report was these husks — 0 files under them). `extractHead` expands the skip list with slash-less ancestors and the python extractor compares the slash-stripped member name: **python's `tarfile` strips the trailing slash from directory `TarInfo.name` while `tar -t` display keeps it — never copy the display form into a member-name match.** Dir members also never count toward SKIPPED (privateHead counts blobs only). Fixture rule: a boundary fixture that excludes only single files (`*.secret`) can never see this; production's whole-tree patterns (`/*`, `projects/*`) are the shape to replicate.
- **Placement gate (`pa/scripts/placement_gate.py`, 2026-09-04)**: `gen` derives the public-path projection from `inventory/placement-registry.md`; `check` refuses mirror-new files matching no public-eligible row (exit 0/2/3/4 = ok/refusal/stale/usage — argparse's default usage exit 2 is overridden to 4 so it never collides with refusal). - **AI-204 (2026-09-05): `.gitignore-public` is GENERATED, never hand-edited** — `gen --gitignore` emits it from the placement registry's Boundary lines (N3) feature cells, each keyed `L<n>:<exact line text>`, projected verbatim in file order under a fixed 2-comment-line header.
