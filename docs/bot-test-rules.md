# Bot test rules (extracted from projects/telegram-bot/CLAUDE.md 2026-09-07 — budget-pressure split; the pointer line lives in the scoped brain)

- **Test rule**: src/tests holds only `.ts` — run-tests.mjs enumerates dist/tests ONLY, so a compiled `.js` stranded in src/tests sits dark forever (last stray untracked 2026-09-06, AI-211).
- **Test rule**: send bodies MdV2-escaped (strip `\`); gates fail-closed on stale dist — build first (`PA_ALLOW_STALE_DIST=1` escape). Never latch
  (trackPendingWork) a test-side fire-and-forget where REAL `process.exit` can fire (poll-loop-callbacks) — the latch turns the no-op drain into a
  real wait and darkens the file; latch only in exit-neutered files (AI-172). Frozen-string pins assert
  EXACT equality, never startsWith/includes — a prefix pin can't count colons and passed an inherited `label::` defect (AI-209, 2026-09-06).
- **Test rule**: fire-and-forget lane tests (executor wake/resume) must accept the SETTLED durable end-state (executor-bumped `runSeq`, completion-written `lastResult`), not only a transient `status: 'running'` poll — on a fast host the whole run closes before the first read (CI-linux-only red, 2026-09-06); keep the in-flight branch for slow hosts.
- Test fixtures use the synthetic id family (-1001234567890, threads 5001/5002), never real chat/thread ids or repo paths — the public mirror tracks src/tests.

- **Test rule**: a forced `sleep` gap between timestamp-ordered fixture groups is not a clock guarantee — on coarse-`Date.now()` runners (CI-macOS) the sleep can elapse inside one clock tick and both groups stamp the same millisecond; loop until the clock itself confirms the gap (`while (Date.now() - from < N) await sleep(...)`) wherever a test asserts timestamp-derived ordering (task-lane-activity CI red 34062205071, fixed d16a7fe, 2026-09-07).

- **Test rule**: a Telegram-mock phase gate that waits a fixed delay after a signal — for example 600 ms after `sendChatAction` — races the real registration or state write it is meant to detect, and it goes flaky under load. Poll the actual dependency the code under test reads instead, such as `listWorkerPids()` for the `/stop` kill path, never a clock guess. Bound every such poll with a hard mock-level timeout that throws, plus a per-test `{ timeout }`, or an unbounded poll hangs `runPollLoop`'s `while (!signal.aborted)` loop instead of failing. Any artificial delay used to prove a known-bad path must sit after cancellation checkpoints, such as in the fixture's `check:` command, never before `runWithFailover`'s pre-spawn stop check. Before that check, a `/stop` cancels the dispatch outright and the test hangs forever (`steer-text-safety.test.ts` S1/M1, commit e4f2435).

- **Test rule**: batched-uptake fold tests must hold an IN-FLIGHT turn first — an idle-topic same-getUpdates-batch pair NEVER folds, because the per-update saveState yield runs the head's whole turn before the follower registers (AI-209).
- **Test rule**: `run-tests.mjs` refuses a stale dist (AI-180) — `npm run build` before any scoped run; positional args filter by dist test basename EXACTLY (`node scripts/run-tests.mjs thread-executor`) — a prefix or typo silently skips the file.
- **Test rule**: a TASK_RULES-pinned prompt-triangle bullet stays apostrophe-free — in the single-quoted TS string the apostrophe lands in the source as `\'`, so the frozen-bullet sync test's byte-exact `includes` against the source file fails ("what you're doing" is written "what you are doing" for exactly this reason; 2026-09-14 progress-posting bullet).
- **Test rule**: NEVER run multiple bot test files via raw `npx tsx --test a.test.ts b.test.ts` — it runs them in PARALLEL against shared app-log/test state (log lines, close-call counts, deferral logs race); failures look like implementation bugs but are test-runner contention. Always use the repo runner (`npm test -- <scoped-files>` or `node scripts/run-tests.mjs <basename>`), which serializes/isolation-manages the suite (AI-249/250/251 wave, 2026-09-15 — 4-file raw run failed 3/4; the spec's `npm test` gate passed 463/463).

- **Test rule**: a `runPollLoop` command-reply test must never assert `sendCalls[0]` — ambient startup sends (per-topic pin refreshes, dashboard writes) can precede the command's reply depending on how many fixture topics exist and on full-suite load; the assertion goes red under the full suite and green scoped (the `/merge` unlinked-topic test, fixed 2026-09-20). Assert `sendCalls.some(c => c.body.includes(<pinned text>))`, and pin-refresh-noisy fixtures get the same treatment as the `/merge` valid-path sibling.
