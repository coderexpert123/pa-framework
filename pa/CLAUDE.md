# Agentic Brain — pa CLI (`pa/`)

Auto-loads on any read under `pa/`; carries pa-internal detail.
Subsystem detail lives in `docs/pa-*.md` — read the named file before touching that subsystem.

- **Agent bus (`pa bus`, `lib/bus-queue.ts`, `docs/bus.md`, 2026-09-16; soft-read 2026-09-17)**: durable address-keyed messaging between agent sessions. Every session has an address — `pa bus whoami` derives `provider@repo` from cwd (override via `PA_BUS_ADDRESS` or `PA_WORKER`). Provider detection: `PA_BUS_PROVIDER`/`PA_WORKER` pin, then `OPENCODE`→opencode, `KGCLAUDE_SESSION`→kgclaude, `CLAUDECODE`→claude, `ANTIGRAVITY_AGENT`→agy, `CHISEL_SESSION_DB`→devin, `CODEX_CLI_PATH`→codex (`detectBusProvider` + all three hook `_provider()` chains, OPENCODE first among ambient); hooks resolve the true session-host pid via `_host_pid.py` (ancestor walk to the provider image — never `getppid()`, AI-261). Send `pa bus send <addr> --from <self> --body "..." [--reply-to <id>]`; receive `pa bus inbox <addr>` (SOFT READ — stamps a `readBy` receipt, keeps the envelope; `--peek` reads receipt-free, `--consume` pops) or `bus_inbox` MCP tool. Queues at `~/.pa/queues/<addr>.jsonl` (`:`→`+` in filenames); cursor at `<addr>.cursor.json` is the liveness record (touched on inbox/wait/spawn/hook, NOT send). Registry at `~/.pa/queues/registry.json` maps address → `{capabilities, worker, spawn, pid}` — `capabilities` arms delivery: `hooks` for headed sessions, `acp` for live ACP sessions, `spawn` for offline workers. Delivery arms chosen at send time by liveness probe: offline → drain spawns worker via `executeWorker` (peek+ack at-least-once, `PA_BUS_ADDRESS` env set on spawn); live-ACP → `deliverViaAcp` steer; headed → hook injection (`PostToolUse`/`Stop` for claude, agy adds `SessionEnd` — agy 1.2.4 caveat: hooks.json loads but no command hook has been observed dispatching live, drain/bus_wait carries delivery until it does; `PreToolUse`/`UserPromptSubmit`/`PostCompaction`/`Stop` for devin — no PostToolUse exists there, `PA_HOOK_EVENT` env stamps the event name, `AfterTool`/`AfterAgent` for deprecated gemini); expecting → `bus_wait` (fs.watch). Envelope expiry: `bus-prune` daily job (24h / 200 entries). `BUS_MAX_HOPS=8` dead-letters back to sender. Native christening: claude `--name`, gemini `--session-id`, agy/devin/codex none (prompt-borne). Content-hash dedup (`sha256(to|json(body)|reply_to)`). Untrusted-payload rule enforced in every prompt/injection. MCP tools (`bus_send`/`bus_inbox`/`bus_wait`/`bus_list`/`bus_whoami`) registered in all 4 CLIs via `pa mcp serve`. Full protocol in `pa/docs/bus.md`; new-CLI checklist `docs/cli-onboarding.md`.

- **Model router (`lib/model-router/`, `docs/model-router.md`, 2026-09-18)**: optional per-turn router beside the judge ladder. Two-stage gate: config block absent = off, zero logging; block present (even `enabled: false`) = SHADOW — one JSONL line per routed turn to `~/.pa/model-router-shadow.jsonl`, topic key only, never turn text; `enabled: true` lets the router decide unpinned turns. Config ORDER IS THE RANK; z.ai workers move to the END of the candidate order inside the peak window. Effort projection is explicit — a knobless worker under high need yields `recategorize`, never a silent downgrade. Daily `model-router-cooldown-normalize` job prunes shadow AND telemetry lines >90d and clears expired cooldowns. Module imports need `../../` — one level deeper than `lib/`. Read `docs/model-router.md` before touching routing. Orchestrator extension (2026-09-19): the classifier is ONE ask of up to 8 questions (tier, score, placement+targets, steer_wait, chain — the chain decision is the answer's `probabilities` map), parsed through the LENIENT typesafe-client variant with per-question fail-open AT THE PARSE BOUNDARY (only tier/score failure fails); `orderCandidateChain` orders the failover chain by those probabilities (never pre-filtered); `deprecate_pins` defaults ON for turn dispatch when the block exists (explicit `false` restores pins — fixtures with a `model_router` block must set it to keep byte-identity); `availability.ts` is a TTL cache (default 5000, env `PA_MODEL_ROUTER_AVAILABILITY_TTL_MS`, `0` off) consumed ONLY by the router's resolve path — the failover ladder's per-attempt checks stay uncached. Surfaces (`fallback`/`steer`/`placement`) stage shadow-first; flips are one config edit each.

- **Python in example skills (install trial 2026-09-18)**: `resolvePythonCommand` (lib/python.ts) covers pa-internal spawns only — a skill's `cmd:` frontmatter and instruction text run through a RAW shell, so `python` dies on macOS (ships `python3` only). Example skills use the portable chain `python3 X || python X` (`||` works in cmd.exe AND POSIX sh; the WindowsApps `python3` stub exits non-zero and falls back). New example skills must follow this pattern.
- **Test discipline**: scoped runs via `npm test -- <bare-basename>`; full detail in `docs/pa-test-discipline.md` — read it before running or writing tests.
- **Build/dist**: `@build` is auto-acquired by build/test (never claim by hand); `assertDistFresh` fails closed on stale dist — build before every test. Full detail in `docs/pa-locks-and-state.md`.
- **Scheduler artifacts deploy only via `pa schedules sync`, never via a build** (2026-09-16): the VBS launcher and POSIX watchdog script that `scheduler.ts` generates reach disk only when sync runs; `pa schedules list` prints whether the on-disk launcher matches this build. Read `docs/catchup-watchdog.md` before touching `commands/catchup.ts`, the launcher generators or `lib/stall.ts`.

- **Capability ladder (`pa init --provision` → `lib/provision.ts`, 2026-09-18)**: discover (PATH CLIs + API keys, presence only) → ask (collisions route here from `KeyCollisionError`, never an overwrite) → keys-only / free-tier fallback (opencode first-class, Devin best-effort) → preserve ask (`git_workflow.enabled`; destination = the user's fork as a PR) → degraded floor. All IO is injected (`ProvisionIo`) — the ladder is unit-testable headless; generated config passes `assertNoOperatorPaths` (A6 placeholder set + the real `~/.pa/operator-identifiers.txt` on re-gate, which reads the USER home, NOT PA_HOME). **Scripted-drive gotcha (install trial 2026-09-18):** the CLI's ask flow creates a fresh readline interface per question on shared stdin — an all-at-once piped stdin is buffered by the first interface and every later ask starves (on Windows the ladder dies); `pa/scripts/install_trial.sh` feeds one paced `no` per 0.4 s as the workaround. A headless provision path does not exist yet.

- **Install acceptance (`pa verify-install [--json] [--skill <name>]` → `commands/verify-install.ts`, 2026-09-18)**: machine-observable acceptance probes — health FAIL-count, one example skill end-to-end through loadSkill with a fresh non-empty outbox file (D4 delivery floor), one worker reply (≥16 chars) or the verbatim `DEGRADED_FLOOR_MESSAGE`, coexistence surfaces key-diffed against snapshots minus `addedKeys` (`unregisteredChanges` — the only check that can SEE an unregistered edit), a real applyAdditive→restore byte-identical round-trip, and the user-facing report linted by the J1 jargon arm. `--json` emits the pinned schema {verdict PASS|DEGRADED|FAIL, degradedFloor, checks[]} — PASS rides alongside `degradedFloor: true`; DEGRADED is reserved for a non-floor WARN. All branches injectable (`VerifyInstallIo`); the skill and restore probes run the real engine over fixture skills in a temp `PA_HOME`. Gotchas (verifier 2026-09-18): `--json` stdout must stay parseable — in-process worker progress lines are rerouted to stderr during collection; Telegram-absence FAILs (bot-process, secrets) reclassify to WARN per D4, so `pa health` FAIL-count is NOT the raw count; the reminders probe seeds a due reminder when the skill dir has no store (seed file removed after) or the store has no due entries (probe row appended, then filtered out after the run). Since 2026-09-20 `pa health`'s workers row emits WARN (not FAIL) when every configured worker is unavailable — the degraded floor — so a zero-CLI install yields no workers FAIL row at all; all-cooling stays FAIL.
